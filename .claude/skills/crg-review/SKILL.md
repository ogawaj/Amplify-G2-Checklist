# レビュー（仕様・設計・セキュリティ・品質の総合レビュー）

`reviewer-spec` エージェントによる 3 ペルソナ（仕様・設計 / セキュリティ / 品質・パフォーマンス）の総合コードレビュー + FAIL 時の自動修正フロー。`crg-implement` のレビュー部分もこのスキルを呼び出して共通化する。

JSDoc / DRY / 過大スコープの専用レビューは別スキル（`/crg-check-jsdoc` / `/crg-check-dry-scope`）の担当。

## Step 0: レビュー対象の選択

引数の種別で分岐：

1. **ステアリングディレクトリ**（パスに `doc/steering/` を含む）→ ステアリングコンテキスト付きレビュー
2. **ファイル / ディレクトリ** → 指定パスをレビュー対象
3. **引数なし** → `git diff --name-only HEAD` および `git status --short` から変更ファイルを抽出
4. 対象が 0 件の場合は処理を中断：

> ⚠ レビュー対象がありません。`git status` で確認するか、対象パスを引数で指定してください。

## Step 1: reviewer-spec の起動

Agent ツールで `reviewer-spec` サブエージェント（`.claude/agents/reviewer-spec.md`）を起動する。

**プロンプト（ステアリングディレクトリ指定の場合）：**

```
ステアリングディレクトリ: {タスクサブディレクトリのパス}

上記のステアリングドキュメントに基づいて実装コードをレビューしてください。
```

**プロンプト（ファイル / git diff の場合）：**

```
レビュー対象ファイル:
{Step 0 で抽出したファイルの一覧}

上記の実装コードを `.claude/rules/` 配下のルール（architecture.md / architecture-db.md / coding-standards.md / coding-standards-db.md / api-design.md）に基づいてレビューしてください。
```

## Step 2: レビュー結果のハンドリング

### PASS の場合

ユーザーに完了報告を行い、Step 3 に進む。

### FAIL の場合

1. レビューで検出された問題点をユーザーに提示する
2. ユーザーに次のアクションを選択してもらう：
   - **自動修正**: 修正サブエージェントを起動して問題を修正し、再レビューする
   - **手動修正**: 問題点の一覧を提示して終了する

### 自動修正を選択した場合

レビューで指摘された問題点の担当範囲に応じて、該当するサブエージェントを **並列** で起動する。

- `amplify/` や `shared/` の問題 → `backend-implementer`
- `src/app/services/`, `src/app/repositories/` 等の問題 → `frontend-logic-implementer`
- `src/app/components/`, `src/app/hooks/` 等の問題 → `frontend-ui-implementer`

**各サブエージェントへのプロンプト（共通）：**

```
{ステアリングディレクトリ指定の場合のみ:}
ステアリングディレクトリ: {タスクサブディレクトリのパス}

## 前回のレビューで指摘された問題点

{該当エージェントの担当範囲に関する問題点をここに記載}

上記の問題点をすべて修正してください。修正後、再度 `npx tsc --noEmit` と `npm run lint` を実行してエラーがないことを確認してください。
```

修正後、Step 1 の `reviewer-spec` を再度起動する。

**修正→レビューのループは最大 2 回まで。** 2 回目のレビューでも FAIL の場合は、残りの問題点をユーザーに報告して終了する。

## Step 3: 完了報告

以下を報告する：

- レビュー対象（ステアリングディレクトリ / ファイル一覧）
- レビュー結果（PASS / 残問題点）
- 自動修正を実施した場合は修正内容のサマリ

## ルール

- サブエージェントのプロンプトには対象（ステアリングディレクトリ or ファイル）を必ず含める
- 修正ループは最大 2 回までとし、無限ループを防ぐ
- 自動コミットしない（ユーザーが指示するまで待つ）
