# 実装・レビュー（サブエージェント方式）

ステアリングドキュメントに基づいて、カスタムサブエージェントで実装とコードレビューを行います。

## Step 0: タスクサブディレクトリの選択・検証

1. ユーザーがタスクサブディレクトリを指定している場合はそれを使用する
2. 指定がない場合は以下の手順で選択する：
   a. `doc/steering/` 配下のステアリングディレクトリを一覧表示し、ユーザーに選択してもらう
   b. 選択されたディレクトリの `plan.md` を読み込み、タスク一覧を表示する
   c. タスクサブディレクトリ（`task-NN-*`）を一覧表示し、ユーザーに実装するタスクを選択してもらう
3. 選択されたタスクサブディレクトリに以下の3ファイルが存在するか確認する：
   - `requirements.html`
   - `design.html`
   - `tasklist.html`
4. **いずれかが存在しない場合は処理を中断する：**

> ⚠ ステアリングファイルが不足しています。
> 先に `/crg-create-steering-task` でステアリングファイルを作成してください。

5. 3ファイルをすべて読み込み、実装内容を把握する

## Step 1: 実装サブエージェントの起動

以下の 3 つのサブエージェントを **並列** で起動する。

| サブエージェント             | ファイル                                       | 担当                                          |
| ---------------------------- | ---------------------------------------------- | --------------------------------------------- |
| `backend-implementer`        | `.claude/agents/backend-implementer.md`        | amplify/ 全層（Handler・Service・Repository） |
| `frontend-logic-implementer` | `.claude/agents/frontend-logic-implementer.md` | フロントエンド Service・Repository 層         |
| `frontend-ui-implementer`    | `.claude/agents/frontend-ui-implementer.md`    | フロントエンド Component・Hook 層             |

**各サブエージェントへのプロンプト（共通）：**

```
ステアリングディレクトリ: {タスクサブディレクトリのパス}

上記のステアリングドキュメントに基づいて実装を行ってください。
```

> **注意:** tasklist.html に該当タスクがないエージェントは自動的にスキップされる。

## Step 2: レビュー実行

`/crg-review` スキルを呼び出して、レビューサブエージェントの起動・PASS/FAIL ハンドリング・FAIL 時の自動修正ループ（最大 2 回）までを実行する。

引数として、Step 0 で選択した **タスクサブディレクトリのパス** を渡す（ステアリングコンテキスト付きレビュー）。

> `crg-review` 側でレビューフロー一式（`reviewer-spec` エージェント起動 / 修正サブエージェント並列起動 / 再レビュー）が実装されているため、本スキルではこのステップを委譲する。

## Step 3: 完了報告

以下を報告する：

- 実装されたタスクの一覧
- 変更されたファイルの一覧
- `crg-review` の結果（PASS / 残問題点）
- 次のステップの案内：永続的ドキュメントの更新が必要な場合は `/crg-update-persistent` を案内

## ルール

- ステアリングドキュメントの内容と矛盾する実装を行わない
- サブエージェントのプロンプトには必ずステアリングディレクトリのパスを含める
- レビュー / 自動修正は `crg-review` に委譲する
