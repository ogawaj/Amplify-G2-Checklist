# 永続的ドキュメント更新

改修後の実装内容を反映して、`doc/persistent/` 配下の永続的ドキュメントを更新します。

## 手順

### Step 0: 現状把握

1. `doc/persistent/` 配下の永続的ドキュメントを読み込む
2. `doc/persistent/` の git 最終更新日時を取得する（`git log -1 --format="%ai" -- doc/persistent/`）
3. その日時以降に変更されたステアリングファイルとソースコードを特定する:
   - `git log --after="<最終更新日時>" --name-only -- doc/steering/ src/ amplify/` で変更コミットと対象ファイルを一覧化
   - 該当するステアリングディレクトリの `requirements.html`、`design.html` をすべて読み込む
4. 変更されたソースコード（`src/`、`amplify/`）を確認し、現在の実装状態を把握する

**変更がない場合：** 永続的ドキュメント更新以降に変更がなければ、「更新不要です」と報告して終了する。

### Step 1: 差分分析

永続的ドキュメントの記載内容と、今回の改修内容（ステアリングファイル + 実装）を比較し、更新が必要な箇所を洗い出す。

更新箇所の一覧をユーザーに提示し、**承認を得てから更新に進む。**

### Step 2: ドキュメント更新

承認された箇所のみ更新する。

1. `product-requirements.md` を更新（必要な場合）→ **ユーザーの承認を待つ**
2. `functional-design.md` を更新（必要な場合）→ **ユーザーの承認を待つ**

**重要：** 1 ファイルごとに必ずユーザーの確認・承認を得てから次に進む。フィードバックがあれば修正する。

### Step 3: 完了報告

更新したファイルの一覧と変更概要を報告する。

## ルール

- 実装されていない内容を追加しない。現在のコードに基づいて記述する
- 今回の改修に関係ない箇所は変更しない
- 図表（Mermaid 等）も実装に合わせて更新する
