# ステアリング計画作成

開発作業をタスクに分解し、`doc/steering/` 配下に計画ファイル（plan.md）を作成します。

## 前提確認

1. `doc/persistent/` 配下に永続的ドキュメントが存在するか確認する
2. **存在しない場合は、以下の警告を出して処理を中断する：**

> ⚠ `doc/persistent/` に永続的ドキュメントが見つかりません。
> 先に `/crg-create-persistent` で永続的ドキュメントを作成してください。

3. 存在する場合は、永続的ドキュメントをすべて読み込み、プロダクトの全体像を把握する

## 手順

以下の手順を **厳密に** 順番通り実行してください。

### Step 0: ヒアリング

ユーザーに以下を質問し、回答を得てから次に進む：

1. **どのような開発・改修を行うか？**（目的・背景・やりたいことを自由に説明してもらう）
2. **開発タイトル**（ステアリングディレクトリの命名に使用する短いタイトル）

### Step 1: ステアリングディレクトリ作成

`.claude/rules/document.md` の命名規則に従い、ディレクトリを作成する。

```bash
mkdir -p doc/steering/[YYYYMMDD][連番]-[開発タイトル]
```

※ YYYYMMDD は本日の日付を使用する

### Step 2: タスク分解・plan.md 作成

永続ドキュメントとヒアリング内容をもとに、開発作業をタスクに分解する。

**plan.md の構成：**

```markdown
# [開発タイトル] 計画

## 目的・スコープ

[全体の目的と対象範囲を記述]

## タスク一覧

### task-01-xxx

- **概要**: [タスクの目的・何を実装するかを具体的に記述。複数行可]
- **依存**: なし

### task-02-yyy

- **概要**: [タスクの目的・何を実装するかを具体的に記述。複数行可]
- **依存**: task-01

### task-03-zzz

- **概要**: [タスクの目的・何を実装するかを具体的に記述。複数行可]
- **依存**: なし

## 推奨実行順序

1. task-01-xxx — [理由]
2. task-03-zzz — [理由]
3. task-02-yyy — [理由: task-01 に依存]
```

- タスクのディレクトリ名は `task-NN-title` 形式（NN は2桁ゼロ埋め）
- 小規模な開発でも最低1タスクとして分解する
- 依存関係がある場合は明記する
- 概要には `/crg-create-steering-task` で requirements.html / design.html / tasklist.html を作成するのに十分な情報を記述する

plan.md を作成したら **ユーザーの承認を待つ**。フィードバックがあれば修正する。

### Step 3: 完了報告

plan.md が承認されたら、以下を案内してください：

1. 作成したファイルの一覧
2. ステアリングディレクトリのパス
3. 次のステップとして `/crg-create-steering-task` で各タスクのステアリングファイルを作成できること

## ルール

- 永続的ドキュメントの内容と矛盾しないようにする
- 不明点がある場合はユーザーに質問して明確化する
- タスクの粒度は `/crg-implement` で1回の実行単位になる程度にする
