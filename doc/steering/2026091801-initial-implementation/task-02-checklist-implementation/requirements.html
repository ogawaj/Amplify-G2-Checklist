Requirements

task-02: CheckList 全機能の実装

サマリ

CheckList の全機能（F-01〜F-15）と全画面（S-01〜S-09）を実装する。 要求は doc/persistent/product-requirements.md、実現方式は doc/persistent/functional-design.md、 画面イメージは doc/persistent/mockup/ を正とする。

フェーズA（データモデルと共通層）→ B（認証）→ C（一覧）→ D（詳細）→ E（持ち物編集）→ F（カテゴリ・タグ管理）→ G（CSV入出力） の順に進め、各フェーズの完了時点でビルドが通る状態を保つ。

ユーザーストーリー

  • 家族として、共有されたアカウントでサインインし、同じチェックリストを見ながら準備を分担したい（US-23・US-24）
  • 利用者として、対象者や用途ごとに複数のチェックリストを作成・複製・削除したい（US-01〜US-04）
  • 利用者として、持ち物にカテゴリ・タグ・1日あたりの必要数を設定して整備したい（US-05〜US-08）
  • 利用者として、カテゴリとタグを追加・改名・並べ替え・削除して絞り込みの軸を整えたい（US-09・US-10）
  • 利用者として、不要になった持ち物を選んでまとめて削除したい（US-11・US-12）
  • 利用者として、行き先タグで絞り、日数から必要数を出し、チェックしながら荷造りしたい。次の準備は1操作で初期化したい（US-18〜US-22）
  • 利用者として、持ち物をCSVで書き出し、表計算ソフトで直して取り込み直したい（US-13〜US-17）

受け入れ条件

product-requirements.md の AC-01〜AC-11 をすべて満たすことを前提に、本タスク固有の条件を次のとおり定める。

  • S-01〜S-09 のすべてが functional-design.md §ルートパス定義のパスで開ける
  • 未認証で (auth-page) 配下を開くと /sign-in へ遷移し、ルート（/）は認証状態に応じて振り分けられる
  • 持ち物の追加・編集、カテゴリ・タグの追加・改名が、一覧上の直接入力で完結する（別画面・ダイアログを挟まない）
  • 破壊的操作（チェックリスト削除・一括削除・一括リセット・CSV取り込み）はいずれも確認操作を挟む
  • 準備状況のチェックは行の右端、削除対象の選択は行の左端に配置され、形と色でも区別できる
  • スマートフォン幅（768px未満）で横スクロールが発生せず、CSV入出力への導線が表示されない
  • 持ち物150件規模で、詳細画面の表示・タグ絞り込み・日数変更・一括リセットが非機能要件の目標時間内に収まる
  • Lambda 関数が1件も追加されていない
  • shared/ が再作成されていない
  • npm run lint・npx tsc --noEmit・npx tsc --noEmit -p amplify/tsconfig.json がエラー0で通り、npm run build が成功する
  • npm run sandbox で4モデルを反映でき、実際のサインインから一連の操作が動作する

制約事項

  • task-01（サンプルコード削除）の完了が前提。未完了の場合は先に実施する
  • Lambda 関数を作らない。一括処理はフロントエンドの Service 層に置く（functional-design.md §一括処理）
  • shared/ は使用しない。共有定義は src/app/ 配下に置く
  • レイヤー構成（Component → Hook → Service → Repository）を守る。Component にロジックを書かず、Hook から Repository を直接呼ばない
  • src/lib/shadcn/ui/ を直接編集しない。必要ならラップしたコンポーネントを作る
  • スコープ外（複数アカウント共有、外出履歴、ドラッグ並べ替え、未チェックのみ表示、外部共有・印刷、CSVのスマートフォン対応、カテゴリ・タグの一括削除、通知、オフライン利用）に手を出さない
  • モックは配色・コンポーネントの確定仕様ではない。レイアウトと情報設計の参照に留める
