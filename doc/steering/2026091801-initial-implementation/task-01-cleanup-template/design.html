task-01: テンプレートのサンプルコード削除

実装アプローチ

  • 葉から根の順に削除する。参照される側（Repository・Service）ではなく、参照する側（Component・Hook）から消し、各段階で両スコープの tsc --noEmit（ルート・amplify/tsconfig.json）が通る状態を保つ
  • ホーム画面はヘッダーだけ残す。components/home/index.tsx からサンプル3枚のカードとダイアログを削除し、アプリ名・環境バッジ・サインアウトのヘッダーだけを残す。task-02 のフェーズB でこのヘッダーを認証済みレイアウトに転用する
  • GraphQL スキーマは空のモデル集合にしない。a.schema({}) は型エラーになるため、Todo のモデル定義だけを残す（設計判断を参照）
  • 削除は git rm で行う。ディレクトリ単位の削除は git rm -r を用いる
  • 検証は lint → tsc → build の順。参照漏れは型検査で、未使用 import は lint で検出する

設計判断

データモデルを空にしない

a.schema({}) はモデル0件を受け付けず型エラーになる（引数の型が never に解決される）。 as never で回避すると architecture.md の設計原則8（型アサーションで型チェックを迂回しない）に反するため採らない。

Todo のモデル定義だけを残し、task-02 フェーズA で4モデルを追加する際に削除する。参照元（Hook・Service・Repository・ホーム画面）は本タスクですべて削除するため、残るのはスキーマ上の定義のみとなる。 スキーマ変更とアプリ層の変更を同じコミットにまとめる規約（architecture-db.md）にも合い、空のスキーマを sandbox に反映する状態も生じない。

amplify/common/ は削除しない

amplify/backend.ts が ./common/services/env-variable-service から getEnvVariable() を import し、環境名（ENV_NAME）の解決とタグ付与に用いている。 削除対象は amplify/functions/ 配下の common/ のみで、amplify/common/ は残す。

影響範囲

  • 変わる: ホーム画面の本体（3カードが消え、ヘッダーのみ）、GraphQL スキーマ（Todo のみ）、デプロイ資材（Lambda 2件が消える）、scripts/prepare-sandbox.cjs（削除したディレクトリへの生成対象を除去）
  • 変わらない: 認証設定、環境変数の仕組み、パスワードポリシー、タグ付与、shadcn/ui、ルーティング構成
  • 一時的に壊れるもの: なし。削除する側と参照する側を同じタスクで消すため、完了時点で lint・型検査・ビルドはすべて通る
  • 後続への引き渡し: ヘッダーの実装は task-02 フェーズB で認証済みレイアウトに転用する。Todo のモデル定義はフェーズA で4モデルと入れ替える

デプロイは task-02 のモデル追加とまとめて行う（requirements.html の制約事項）。 本タスクの検証はローカルの npm run lint / npx tsc --noEmit / npx tsc --noEmit -p amplify/tsconfig.json / npm run build で行う。ルートの tsc は amplify/ を検査しないため、backend.ts と data/resource.ts の編集は後者で確認する。
